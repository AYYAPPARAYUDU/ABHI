# ADR-0005: Desktop and Browser Automation Grounding Hierarchy and Safety Leases

**Status:** ACCEPTED  
**Date:** 2026-09-25  
**Author:** Software Engineering & Architecture Team  

## 1. Context & Problem Statement
Phase 5 introduces autonomous physical operation of the Windows 11 desktop and Playwright web browsers. Unrestricted, ungrounded, or unverified AI interaction with the host operating system creates critical failure risks:
1. **Coordinate Hallucination:** Directly injecting (x, y) coordinates generated by LLMs leads to clicking unintended controls or off-target regions.
2. **Uncontrolled Execution & Runaways:** Long-running or stuck automation scripts could monopolize user input without an auto-expiring lease or emergency stop.
3. **Human-AI Input Contention:** If the user moves the mouse or types while automation is active, conflicting inputs can corrupt user data or misclick destructive dialogues.
4. **Security & Destructive Operations:** System commands, file deletions, credential changes, or transactional actions require formal consent barriers.

## 2. Decision
1. **Four-Tier Grounding Hierarchy:**
   * **Level 1 (Preferred): Windows UI Automation (UIA) & DOM Locators.** Ground UI elements by semantic `AutomationId`, `Name`, `ControlType`, or CSS/XPath/role locators.
   * **Level 2: Native Application Accessibility APIs.** Use win32 accessibility or app-specific trees.
   * **Level 3: Screen OCR & Visual Grounding.** Extract OCR bounding boxes to locate visual tokens when semantic trees are unavailable.
   * **Level 4 (Strict Fallback): Raw Coordinates.** Allowed only with pre-action and post-action visual verification. Model hallucinated coordinates are rejected.

2. **Automation Execution Lease Contract:**
   * Every physical automation session is bound to an auto-expiring `AutomationLease` (maximum TTL 30s per sub-task).
   * Actions fail immediately if the lease expires, is cancelled, or is revoked.

3. **Multi-Frame Gesture & Consent Confirmation:**
   * `THUMBS_UP` serves as a candidate consent signal only after sustained detection (>= 5 consecutive frames, confidence >= 0.85, 1000ms debounce).
   * `OPEN_PALM` serves as an immediate, low-latency Emergency Stop signal that cancels all active automation leases and freezes physical input injection.

4. **Human Input Contention Protection:**
   * Physical mouse movements or keypresses by the human operator trigger an immediate automation pause, yielding control back to the user.

5. **Dual-State Verification for Physical Actions:**
   * Preconditions must match expected system state prior to execution.
   * Postconditions (UI state change, window title, DOM mutation) are physically observed after execution. If expectations fail, the action is stopped or retried under policy.

## 3. Alternatives Considered
* **Direct PyAutoGUI Coordinate Scripting:** Rejected due to high risk of coordinate drift and window misalignment.
* **In-Process Automation Injection:** Rejected because automation crashes or hangs would take down the core Cognitive Gateway.

## 4. Consequences & Tradeoffs
* **Positive:** Complete prevention of coordinate hallucinations, 100% human-in-the-loop safety for high-risk operations, clean sub-process crash isolation.
* **Tradeoff:** Level 1/Level 2 semantic tree resolution adds ~15-30ms inspection latency before physical input injection.
